Security

Last updated: 20 June 2026

Klaro handles financial data, so security is built into how it's designed. Here's a plain-language overview of how your data is protected.

Per-user isolation

  • Every record is tied to your account and protected by database row-level security — the database itself refuses to return one user's data to another, even if application code had a bug.
  • Every API request is authenticated and scoped to the signed-in user; cross-account access returns "not found."

Authentication

  • Sign-in is handled by Supabase Auth; passwords are hashed (never stored in plain text), and email verification is required.
  • Sessions use short-lived, signed access tokens (JWTs) that are verified on every request against a public key — no shared secret lives in the app server.

Data in transit & at rest

  • All traffic between the apps and the server uses HTTPS/TLS.
  • Data is stored in managed Postgres (Supabase) with encryption at rest and regular automated backups.
  • On your phone, data is cached locally so the app works offline; uninstalling removes it.

Minimal data & no tracking

  • Klaro stores only what it needs to show your spending. No advertising SDKs, no third-party analytics or trackers.
  • Optional AI categorization sends only a merchant name (never amounts, account numbers, or message text) to classify an unfamiliar merchant.

Secrets

API keys and database credentials live only in the server's environment configuration — never in the app bundle or the public code repositories.
